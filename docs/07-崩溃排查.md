# 07 崩溃排查（闪退诊断）

> 场景：点击「开始检测」后应用直接退出（无 Toast、无错误页）。这通常不是 Java 异常，
> 而是 **native 致命信号** 或 **JNI 中止**——Java 层根本来不及处理。

## 1. 先看应用自己给出的诊断（1.0.3 起）

1.0.3 在每次检测前把「当前阶段」写入应用私有目录 `files/last_stage`，同时把兼容性探测结果写入
`files/compat_probe.txt`。如果进程在某个阶段被信号杀死，**下次启动首页会显示一条黄色横幅**：

```
上次检测在「<阶段>」阶段异常退出（疑似 native 崩溃）。
兼容性探测：pidfd=0 openat2=1 clone3=0 sig=31
```

- `<阶段>` 取值：`probe` / `mount` / `ksu` / `kernel` / `bpf` / `zygisk` / `inject` / `security` /
  `extra` / `sandbox` / `antihook` / `done`。
- `sig=31` 表示子进程被 **SIGSYS**（seccomp 拦截）杀死；`sig=11` 是 SIGSEGV；`sig=6` 是 SIGABRT。
- 若横幅显示 `done` 或没有横幅，说明上次是**正常结束**，崩溃点在 Java 层（会由 `last_crash.txt` 记录堆栈）。

> 把这条横幅截图发给开发者，基本就能定位到模块。

## 2. 抓系统日志（最直接的证据）

```bash
adb devices
adb logcat -b crash -d            # 崩溃缓冲区，通常几行就能看到 Fatal signal
adb logcat -d -v threadtime | grep -iE "aegis|DEBUG|libc|Fatal|signal 31|SIGSYS" | tail -80
```

关注关键字：

| 关键字 | 含义 |
| --- | --- |
| `Fatal signal 31 (SIGSYS)` | 某个系统调用被 seccomp 直接拦截（最常见：`pidfd_open` / `openat2` / `clone3`） |
| `Fatal signal 11 (SIGSEGV)` | 空指针 / 越界 / 栈溢出 |
| `Fatal signal 6 (SIGABRT)` | ART 主动 abort（含 `JNI ERROR: input is not valid Modified UTF-8`） |
| `JNI DETECTED ERROR` | JNI 调用参数非法（通常是字符串编码问题） |

## 3. 1.0.3 针对闪退做的加固

| 加固 | 说明 |
| --- | --- |
| **兼容性探测** | `pidfd_open` / `openat2` / `clone3` 先在一个**一次性子进程**里试调用；若子进程被信号杀死，主进程永久禁用对应调用，改用 `/proc` 路径与 `clone(SIGCHLD)` 回退 |
| **阶段埋点** | 每个模块执行前落盘，崩溃后下次启动可见 |
| **UTF-8 校验** | 证据里的进程名/路径/属性值来自内核，可能是非法 UTF-8；现在在 JSON 转义阶段把非法字节与 4 字节序列替换为 `?`，避免 `NewStringUTF` 让 ART 直接 abort |
| **Java 崩溃落盘** | 未捕获异常写入 `files/last_crash.txt`，下次启动展示 |
| **修复 clock_nanosleep 参数** | 之前少传两个参数导致沙箱等待变成忙等，可能让子进程被过早 kill |
| **clone3 探测** | `clone3` 只在探测通过后使用，否则直接用 `clone(SIGCHLD)` |

## 4. 如果仍然闪退：逐步隔离

1. **设置 → 检测调度 → 关闭「clone3 沙箱」** → 再检测一次。
   - 不崩了 ⇒ 问题在 `sandbox` 阶段（clone3/clone 或子进程代码）。
2. **设置 → 打开「快速模式」** → 再检测一次。
   - 不崩了 ⇒ 问题在跨进程读取或网络时延项。
3. **设置 → 检测项开关**：逐组关闭（先关 `extra` 组的 9 项，再关 `antihook`），二分定位。
4. 若只要打开应用就崩（不是点检测），说明是启动路径问题，优先看 `last_crash.txt`。

## 5. 兼容性探测文件怎么看

`files/compat_probe.txt` 示例：

```
pidfd=0 openat2=1 clone3=0 sig=31
```

| 字段 | 含义 | 影响 |
| --- | --- | --- |
| `pidfd=0` | 本进程不可安全调用 `pidfd_open` | 所有 `/proc` 读取走路径方式（功能不受影响，只是少一条交叉校验路径） |
| `openat2=1` | 可安全调用 `openat2` | `AHK-006` 正常执行；为 0 时该检测项标记为不可用 |
| `clone3=0` | 不可安全调用 `clone3` | 沙箱改用 `clone(SIGCHLD)`（语义等价） |
| `sig=31` | 探测子进程被 SIGSYS 杀死 | 说明该 ROM 的 seccomp 会 TRAP 上述调用；这是**设备特性**，不是应用缺陷 |

## 6. 反馈给开发者时需要提供

1. 首页黄色横幅的截图（或 `files/last_stage` 内容）；
2. `files/compat_probe.txt` 内容；
3. `adb logcat -b crash -d` 的最后 30 行；
4. 设备信息：Android 版本、安全补丁日期、内核版本、ROM 名称（如 CloreOS15）。

有了这四项，基本可以一次定位到具体模块与原因。
