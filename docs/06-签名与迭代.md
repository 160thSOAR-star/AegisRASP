## 2. 密钥在构建里的位置

`app-ui/build.gradle.kts`：

```kotlin
// 口令从本地不入库的 keystore/keystore.properties 读取
val keystorePropsFile = rootProject.file("keystore/keystore.properties")
val keystoreProps = Properties().apply {
    if (keystorePropsFile.exists()) keystorePropsFile.inputStream().use { load(it) }
}
val hasReleaseSigning = keystorePropsFile.exists() &&
    rootProject.file(keystoreProps.getProperty("storeFile") ?: "keystore/aegis-release.jks").exists()

signingConfigs {
    create("aegisRelease") {
        storeFile = rootProject.file(keystoreProps.getProperty("storeFile") ?: "keystore/aegis-release.jks")
        storePassword = keystoreProps.getProperty("storePassword")
        keyAlias = keystoreProps.getProperty("keyAlias") ?: "aegis"
        keyPassword = keystoreProps.getProperty("keyPassword")
    }
}

buildTypes {
    release {
        // 没有本地私钥时留空（产物不签名），有私钥时自动生效
        signingConfig = if (hasReleaseSigning) signingConfigs.getByName("aegisRelease") else null
        isMinifyEnabled = true
        isShrinkResources = true
    }
    debug {
        applicationIdSuffix = ".debug"
        signingConfig = if (hasReleaseSigning) signingConfigs.getByName("aegisRelease")
                       else signingConfigs.getByName("debug")   // 无私钥时退回调试签名
    }
}
```

因此：

- **release**：`com.rasp.detect.aegis`
- **debug**：`com.rasp.detect.aegis.debug`（与 release 可共存，互不覆盖）
- debug 与 release 都用同一证书签名，便于用同一套 `apksigner` 校验规则做自动化。

## 3. 迭代流程（改代码后怎么重新出包）

```bash
# 1. 改版本号（必须！见第 4 节）
#    编辑 app-ui/build.gradle.kts： versionCode += 1，必要时 versionName 变更

# 2. 重新打包
./gradlew :app-ui:assembleRelease

# 3. 校验签名与证书指纹（应始终等于本文第 1 节的 SHA-256）
apksigner verify --print-certs app-ui/build/outputs/apk/release/app-ui-release.apk

# 4. 覆盖安装（同包名 + 同签名 + 更高 versionCode 才能成功）
adb install -r app-ui/build/outputs/apk/release/app-ui-release.apk

# 5. 归档到交付目录
cp app-ui/build/outputs/apk/release/app-ui-release.apk dist/AegisRASP-<version>-release.apk
```

## 4. 版本号规则（最容易踩的坑）

| 场景 | 要求 |
| --- | --- |
| 覆盖升级已安装的 App | **`versionCode` 必须严格递增**，签名证书必须一致 |
| 只改文案/资源 | 同样要递增 `versionCode`，否则 `adb install -r` 报 `INSTALL_FAILED_VERSION_DOWNGRADE` |
| 换了签名密钥 | 会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`；只能 `adb uninstall com.rasp.detect.aegis` 后重装（**数据丢失**） |
| debug 与 release 并存 | 可以，包名不同（`.debug` 后缀），互不影响 |

当前值：`versionCode = 3`，`versionName = "1.0.1"`。

1.0.1 与 1.0.0、1.0.1-rc 使用**同一密钥**（证书 SHA-256 均为 `93:1E:E6:…:DF:C5:AB`），因此已安装
1.0.0 或 1.0.1-rc 的设备可直接 `adb install -r` 覆盖升级，无需卸载。后续每次发版都要继续递增 `versionCode`。

> 1.0.1 是 1.0.1-rc 的转正版本，两者检测逻辑完全一致，差异只在 `versionName` 与 `AboutScreen.kt`
> 的应用内日志文案；因此 1.0.1-rc 的 APK 仍保留在 `dist/` 作为历史记录，但**不再是当前交付物**。

## 5. 常见操作

**查看指纹（不打印私钥）**

```bash
keytool -list -v -keystore keystore/aegis-release.jks -storepass <你的库口令> | findstr /i "SHA256"
```

**验证已安装 APK 与待安装 APK 是否同一签名**

```bash
adb shell pm path com.rasp.detect.aegis
adb pull /data/app/.../base.apk installed.apk        # 需 root 或 debuggable 设备
apksigner verify --print-certs installed.apk
apksigner verify --print-certs app-ui/build/outputs/apk/release/app-ui-release.apk
# 两份证书 SHA-256 相同 => 可以覆盖升级
```

**用 apksigner 手动重签（例如换用别的构建流水线产物）**

```bash
zipalign -f -p 4 unsigned.apk aligned.apk
apksigner sign --ks keystore/aegis-release.jks --ks-key-alias aegis \
  --ks-pass pass:<你的库口令> --key-pass pass:<你的密钥口令> \
  --v1-signing-enabled false --v2-signing-enabled true \
  --out signed.apk aligned.apk
```

**重新生成密钥（仅在确定要放弃旧身份时）**

```bash
keytool -genkeypair -v -keystore keystore/aegis-release.jks -alias aegis \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <新库口令> -keypass <新密钥口令> \
  -dname "CN=Aegis RASP, OU=Security, O=Aegis, C=CN"
```

> 换密钥 = 换应用身份。老用户无法升级，只能卸载重装。

## 6. 签名配置的生产化（已在本仓库应用）

仓库里的 `app-ui/build.gradle.kts` 已改为从 **不入库** 的 `keystore/keystore.properties` 读取口令，
源码本身不含任何明文口令；没有该文件的机器可正常编译，只是产物不签名。

本地需要创建的 `keystore/keystore.properties`：

```properties
storeFile=keystore/aegis-release.jks
storePassword=<你的库口令>
keyAlias=aegis
keyPassword=<你的密钥口令>
```

`.gitignore` 已包含：

```
keystore/*.jks
keystore/keystore.properties
```

CI 场景则用环境变量注入（`ORG_GRADLE_PROJECT_...` 或 `signingConfig` 读取 `System.getenv`），密钥库以 base64 Secret 形式存放。
